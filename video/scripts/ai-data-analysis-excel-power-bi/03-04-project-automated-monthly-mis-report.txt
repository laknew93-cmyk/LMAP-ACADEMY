Welcome to AI for Data Analysis, module 3, lesson 4: Project: Build an Automated Monthly MIS Report.

Here's the difference between someone who "makes reports" and a real MIS professional. The second person builds the report once, and refreshes it every month. In this project, you'll build a pivot-based monthly MIS report that updates in minutes when new data arrives.

Let's set the scene. Sharma Distributors in Nagpur supplies FMCG products to retailers through three branches: Nagpur, Amravati and Wardha. Every month, each branch emails a sales export. Today, Rohit in the head office spends two days copying files together, fixing columns and rebuilding pivots. Your goal is to get that down to under thirty minutes, with most of it spent reviewing rather than building.

The report needs four things. First, sales net of G S T by branch for the month, compared with last month and with target. Second, the top ten products and top ten retailers by sales. Third, the category mix by branch. And fourth, as an optional stretch, collections. That's amount billed versus amount received, and outstanding over sixty days, from a separate receivables sheet.

Now, the architecture. Good recurring reports separate four layers. Input is the monthly files, sitting in one folder. Prepare is Power Query, which combines and cleans them. Calculate is your pivots and SUMIFS, working on the clean Table. And Present is the report sheet, with a fixed layout and charts. There are three rules that make this work. Never type into the clean data or pivots by hand. The only things that change each month are the new files in the folder, plus one Report Month cell. And every number on the Report sheet traces back to the clean Table.

Step one: set up the folder. Create a folder, something like Sharma MIS, with a Data folder inside it. Save each branch's monthly file there with a consistent name, like Nagpur, then the year and month. But consistency in file layout matters more than the names. Same columns, same order, same header row. If branches send different layouts, ask them, politely, with a template, to standardise. That one email can save hours every month. For practice, ask an AI to generate three branch files for August and September 2026, with columns for invoice number, date, branch, retailer code, product, category, quantity, net amount, G S T amount and gross amount.

Step two: combine and clean with Power Query. This works in Excel on Windows, 2016 or later. Microsoft 365 on Mac also supports Power Query, with some differences. First, go to Data, Get Data, From File, From Folder, and select your Data folder. Second, click Combine and Transform Data, and choose the sheet or table to use from the sample file. Third, in the Power Query Editor, apply your cleaning steps. Remove the Source Name column if you don't need it, or keep it to trace rows back to files. Set the data types, with date as Date and amounts as Decimal Number. Trim and clean the text columns, under Transform, Format, Trim. Replace values for known spelling variants. And remove duplicates on invoice number plus product. Fourth, choose Close and Load To, and load it as a Table on a sheet named Data.

Every step is recorded in the Applied Steps list on the right. Next month, you add new files to the folder and click Data, Refresh All, and all the steps re-run automatically.

If a step confuses you, ask an AI. Here's the prompt: "In Power Query, my Date column from the branch files is text like 05 dash 09 dash 2026, which is day, month, year. When I change type to Date it gives errors for some rows. How do I convert it correctly? Explain the steps in the Power Query editor and the M code." The usual answer is to use Change Type, Using Locale, and choose Date with the English India locale, which reads the day first.

Step three: add a control panel. Create a Control sheet. In B2, enter the report month, for example the first of September 2026. Then below it, four cells calculated with EOMONTH: the first day of the month, the last day of the month, the first day of the previous month, and the last day of the previous month. The formulas are in the lesson notes. Name those cells, under Formulas, Define Name, as MonthStart, MonthEnd, PrevStart and PrevEnd. Your formulas become readable, and you only change B2 each month. Also add a Targets table, with branch, month and target.

Step four: build the calculations. Start with the branch summary, using SUMIFS. It has a fixed layout, so it's ideal for the front page. With branches listed down the Report sheet, you build five columns. This month is a SUMIFS of net amount for the branch, between MonthStart and MonthEnd. Last month is the same, between PrevStart and PrevEnd. Month-on-month percent is this month divided by last month, minus one, wrapped in IFERROR to show a dash. Target is a SUMIFS on the Targets table for the branch and MonthStart. And achievement is this month divided by target, again with IFERROR. All five formulas are in the lesson notes below the video. One tip: store the target month as the first day of each month, so it matches MonthStart.

For the top ten products and retailers, use pivots. Create a pivot from the Data table, with Product in Rows and Sum of Net Amount in Values. Add a Timeline, or put a Month field in Filters. Then right-click Product, choose Filter, then Top 10, by Sum of Net Amount. Repeat for Retailer Code.

In Excel 365, you can instead use dynamic formulas that need no refresh clicks. There's a one-line formula in the lesson notes that groups net amount by product with GROUPBY, sorts it largest first, and takes the top ten. As written, it covers every row in Data. To limit it to the report month, GROUPBY has an optional filter argument, so ask an AI to add it for your column names. GROUPBY is newer and may not exist in your version. If you get a NAME error, ask an AI for the equivalent using UNIQUE, SUMIFS and SORTBY. Or just use a pivot, which works everywhere.

For the category mix, build a pivot with Category in Rows, Branch in Columns, and values shown as Percent of Column Total.

Step five: design the report page. On a Report sheet, arrange five things. A title that includes the month, built with a formula that joins "Sharma Distributors, Monthly MIS" with the month name and year from the Control sheet. The branch summary table at the top. The top ten tables, side by side. One or two charts, and Module 5 covers chart choice. And a Notes box for commentary. Use conditional formatting for month-on-month percent, green above zero and red below, and for achievement, red below ninety percent. Keep formatting consistent, using the Indian number format for rupees. There's a custom number format in the lesson notes that shows lakh-style commas. Just copy it in.

Step six: the monthly refresh routine. Write this on a README sheet. There are seven steps. One, save the three branch files for the new month in the Data folder, with the same layout. Two, open the workbook, and change the report month on the Control sheet to the first of the new month. Three, click Data, Refresh All, and wait for it to finish. Four, check the Data row count against the sum of the branch file rows. Five, check the total net amount against the accounts team's sales register for the month. Six, review the Report sheet and update the Notes box. And seven, save it with the year and month in the file name, and send it as a PDF. That fourth check deserves a formula. On the Control sheet, a COUNTIFS on the date column between MonthStart and MonthEnd gives you this month's row count.

Then ask an AI to review your design. Here's the prompt: "Here is the structure of my monthly MIS workbook," and you describe the sheets and key formulas. "What could break when I refresh it next month? Suggest checks I should add."

Now, try it yourself. This project takes sixty to ninety minutes, so pause the video and work through these steps. Step one. Generate August and September files for three branches, and put them in a folder. Step two. Combine them with Power Query. Or, in Google Sheets, stack them on one sheet and use QUERY. Step three. Build the Control sheet, the branch SUMIFS summary, a top ten products pivot, and a category mix pivot. Step four. Design the Report sheet and write the README routine. And step five, test it. Add an October file, change the month, and refresh. Did everything update correctly?

Let's recap. Separate the input, preparation, calculation and presentation layers. Power Query records cleaning steps once, and replays them on every refresh. Drive the whole report from one Report Month cell, using EOMONTH and named cells. Use SUMIFS for fixed front-page tables, and pivots for top ten and mix analysis. And write a refresh routine with built-in control checks, then test it with next month's data.
