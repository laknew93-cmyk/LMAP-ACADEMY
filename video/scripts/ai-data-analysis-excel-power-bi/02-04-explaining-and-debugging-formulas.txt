Welcome to AI for Data Analysis, module 2, lesson 4: Explaining and Debugging Inherited Formulas.

Half of spreadsheet work isn't writing new formulas. It's understanding and fixing the ones someone else left behind. In this lesson, you'll learn to use AI as a patient tutor that explains, audits and repairs formulas, and you'll learn how to check its work.

Let's start with the inherited-file problem. Imagine you've just joined the MIS team at a Nagpur FMCG distributor. The monthly branch report has a cell with a long formula. It's an IFERROR wrapped around a SUMPRODUCT, which multiplies three things together: whether the branch column matches a branch name, whether the date, converted to month-year text, matches a month label, and the net sales column. It runs from row 2 to row 5000. The full formula is in the lesson notes below this video. The person who built it has moved to Hyderabad. And the number in that cell looks low this month. Where do you start?

Step one: ask for a plain-English explanation. The prompt in the lesson notes asks the AI to explain the formula step by step in simple English, as if to a new MIS executive. Then, and this is the important part, it asks what assumptions the formula makes about the data, and what could make it return a wrong number without showing an error. It also gives context: the cell with the branch name, the month label like "Oct dash 26", and which data columns hold the invoice date, branch and net sales. You'll find the full prompt in the lesson notes below this video.

A good explanation will tell you four things. First, it checks each row where the branch equals the branch name, giving a one or a zero. Second, it converts each date to month-year text and checks it equals the month label, again one or zero. Third, it multiplies those with net sales, so only matching rows contribute, and sums them. And fourth, IFERROR turns any error into zero.

But the silent-failure part is where the real value lies. Expect points like these. One, the fixed range ends at row 5000. If the data now has fifty-four hundred rows, the last four hundred are ignored. That's very likely why the number looks low. Two, IFERROR hides problems. If any cell in the sales column contains text, like "NA", the whole formula errors, and IFERROR shows zero instead of warning you. Three, text dates. If some dates are text, the TEXT function won't format them as expected, and those rows won't match. And four, branch spelling. "Nagpur" with a trailing space won't match "Nagpur". So you've gone from "the number looks low" to four testable hypotheses in about two minutes.

Step two: test the hypotheses yourself. Don't take the AI's word for it. Check. Press Control End on the Data sheet to see the last used row. If it's beyond 5000, hypothesis one is confirmed. COUNTA on the date column, minus one, tells you how many data rows exist. A SUMPRODUCT of ISTEXT on the sales column counts text cells there. And the same check on the date column counts text "dates". In those formulas, you'll see a double minus sign. That just converts TRUE and FALSE into one and zero, so SUMPRODUCT can add them up. The exact checks are in the lesson notes.

Step three: ask for a more robust rewrite. Here's the prompt: "Rewrite this formula so that it doesn't break when rows are added, it doesn't hide errors, and a colleague can understand it. I'm on Excel 365. I can convert the data into a Table named Data." A likely answer, once the data is a Table and the month cell holds a real date, the first of the month, instead of text, is a simple SUMIFS. It sums net sales where the branch matches, and the invoice date is between the first of the month and the end of the month, using EOMONTH. The formula is in the lesson notes. It's shorter, faster, grows with the data, and an error in the source will now show up instead of becoming a silent zero. That's a better report, not just a fixed cell.

Next, use Excel's built-in tools alongside AI. AI explanations work best when combined with Excel's own auditing features. There are four worth knowing. First, Evaluate Formula, on the Formulas tab. It steps through a formula one calculation at a time on your real data. Use it to confirm what the AI described. Second, Trace Precedents and Trace Dependents. They draw arrows showing which cells feed a formula, and which cells use it. Third, F9 inside the formula bar. Select part of a formula and press F9 to see what that part evaluates to. Then press Escape afterwards, or the result replaces your formula. And fourth, Show Formulas, with Control and the backtick key. It displays formulas instead of results across the sheet, which is useful for spotting one cell that's hard-coded while its neighbours are formulas. In Google Sheets, clicking a formula cell shows a preview tooltip of the result, and Sheets' built-in AI help, where available, can also explain formulas.

Now let's decode the common error codes. N A usually means a lookup value wasn't found. Fix it with TRIM, check the data types, or add the missing master data. VALUE means a wrong data type, like text in a calculation. Find the text cell, and use VALUE or clean the source. REF means the formula points to a deleted cell or sheet, so you'll need to rebuild the reference. DIV zero means you're dividing by zero or a blank. Use IFERROR, or an IF that checks whether the denominator is zero. NAME means a misspelt function, or a function your version doesn't have. Check the spelling, or use an older alternative. And SPILL means a dynamic array's output is blocked, so clear the cells in the spill range. The full table is in the lesson notes.

When you're stuck, here's a useful prompt: "Cell F12 shows a VALUE error. Here's the formula. The referenced cells contain these values, for example D12 is 1,200 in quotes, and E12 is five percent. What's causing it, and what's the smallest fix?"

Next, build a formula documentation habit. When you finish a complex workbook, ask the AI to help you write a Read Me sheet. The prompt in the lesson notes gives the AI your key formulas, with their cell addresses and purpose, and asks for a short README for the next person. It should cover what each sheet does, where the inputs go, which cells must never be overwritten, and how to refresh for a new month. This is one of the most underrated career moves for MIS professionals. Managers notice when your files can be handed over without a two-hour call.

But what about when AI explanations are wrong? AI assistants sometimes misread argument order, especially SUMIF versus SUMIFS. They can confuse Excel and Sheets behaviour, or describe a function your version doesn't have. So protect yourself in three ways. Test the explanation on two or three rows where you know the answer. Use Evaluate Formula to confirm the intermediate steps. And if the AI says something surprising, ask it, "Are you sure? Show me what this returns for row 7," and check that against the sheet.

Now, try it yourself. This takes about fifteen minutes, so pause the video and work through these steps. Step one. Find the longest formula in any workbook you use at work. Or ask an AI to generate a "messy legacy MIS formula using SUMPRODUCT and nested IFs" for practice. Step two. Ask an AI for a step-by-step explanation and a list of silent-failure risks. Step three. Pick two of those risks and test them yourself, using Control End, ISTEXT checks or Evaluate Formula. Step four. Ask for a more robust rewrite, and compare its result with the original on the same data. And step five. Write a three-line README note for that formula.

Let's recap. Ask AI not just "what does this do", but "what could make it silently wrong". Turn the AI's explanation into hypotheses, and test them on the real data. Combine AI with Evaluate Formula, Trace Precedents and F9 to confirm what's happening. Rewrite fragile formulas with Tables and SUMIFS, so they grow with the data and surface errors. And document key formulas in a README sheet. It makes your work easy to hand over.
